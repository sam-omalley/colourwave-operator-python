# AGENTS.md — colourwave-operator-python

Operational guide for LLM agents working in this repository.
Read this before making any changes.

---

## What this repo is

A Python port of the colourwave-operator project. Three components:

| Component | Directory | Framework |
|---|---|---|
| Demo web app | `app/` | Flask + gunicorn |
| Kubernetes operator | `operator/` | kopf + kubernetes Python client |
| Control-panel UI | `ui/` | Flask + gunicorn + kubernetes Python client |

The CRD schema lives in `crd/` and is shared with the Go version — it is not
generated here, just copied.

## Key patterns

### App (app/app.py)

- `VERSION`, `COLOUR`, `HOSTNAME` read from environment variables.
- JSON logging via a custom `logging.Formatter` subclass. Werkzeug's default
  access log is suppressed (`logging.getLogger("werkzeug").disabled = True`).
- Flask finds `templates/` automatically relative to `app.py`.
- `gunicorn ... app:app` — the first `app` is the module name, the second is
  the Flask instance variable.

### Operator (operator/main.py)

- kopf uses decorators: `@kopf.on.create`, `@kopf.on.update`, `@kopf.on.resume`.
  All three are stacked onto `reconcile()` to mirror kubebuilder's single
  `Reconcile()` function.
- **`on.resume` is required** for startup sync. Without it, existing CRs are
  ignored until their next change event.
- `kopf.adopt(obj, owner=body)` sets owner references — equivalent to
  `ctrl.SetControllerReference` in controller-runtime.
- No `CreateOrUpdate` helper exists in the Python client. Use try/except on
  HTTP 409 to detect "already exists" and fall back to patch.
- Run: `kopf run --all-namespaces main.py`

### UI (ui/app.py)

- `DynamicClient` from `kubernetes.dynamic` — equivalent to Go's
  `dynamic.NewForConfig`. Used because the ColourWave CRD has no generated
  Python clientset.
- `config.load_incluster_config()` with fallback to `load_kube_config()`.
- Harbor is called via the `requests` library. `HARBOR_URL` defaults to
  `https://harbor.lizardnode.com`; in-cluster set it to
  `http://harbor-core.harbor.svc.cluster.local`.
- All routes match the Go UI exactly so the same HTML/JS frontend works
  unchanged.

## Building images

Build from each component's own directory (unlike the Go UI which required
building from the repo root):

```bash
podman build --platform linux/amd64 -t harbor.lizardnode.com/colourwave/app-py:vX.Y.Z app/
podman build --platform linux/amd64 -t harbor.lizardnode.com/colourwave/operator-py:vX.Y.Z operator/
podman build --platform linux/amd64 -t harbor.lizardnode.com/colourwave/ui-py:vX.Y.Z ui/
```

`--platform linux/amd64` is required when building on Apple Silicon.

## CRD

The CRD is identical to the Go version. If the Go operator is already deployed
in the cluster the CRD is already installed — do not re-apply it unless you
intend to replace it.

To install fresh:
```bash
kubectl apply -f crd/colourwave-python.lizardnode.com_colourwaves.yaml
```

## What NOT to do

- **Don't commit secrets** — HARBOR_TOKEN and kubeconfig credentials must be
  injected via environment variables or mounted secrets.
- **Don't use `flask run` in production** — it's single-threaded and not safe
  for concurrent requests. Always use gunicorn.
- **Don't omit `@kopf.on.resume`** — without it the operator ignores all
  existing CRs on startup.
- **Don't regenerate the CRD here** — it lives in the Go project and is
  generated by `controller-gen`. Copy updates from there.
